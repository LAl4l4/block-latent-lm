# 公开时间证明（OpenTimestamps）

每个子目录对应一次时间证明：

- `MANIFEST.txt`：某个 git 提交里每个文件的 SHA-256，开头写明提交号和想法的提出时间；
- `MANIFEST.txt.ots`：OpenTimestamps 证明文件。

## 原理

清单的 SHA-256 被提交到 4 个公共日历服务器（a/b.pool.opentimestamps.org、a.pool.eternitywall.com、ots.btc.catallaxy.com），服务器再把它汇总写进比特币区块链。

- **能证明的：** 这份清单，以及其中列出的每个文件的当前内容，在那个时间点之前就已经存在。
- **不会公开的：** 提交时附加了随机数，服务器连文件的哈希都看不到，更看不到内容。
- **怎么核对：** 任何文件都可以用 `sha256sum` 重新计算，再和清单里的值比对。

## 待完成：升级证明

刚生成的证明处于 pending 状态，要等比特币区块确认，一般需要几小时。之后运行一次升级，把区块链上的证明路径写进 `.ots` 文件：

```
ots upgrade timestamps/2026-10-31-5147a70/MANIFEST.txt.ots
```

也可以把 `MANIFEST.txt` 和 `.ots` 一起拖到 https://opentimestamps.org 网页上验证。网页会自动完成升级，并显示具体的区块时间。

升级后的 `.ots` 文件要提交进仓库。原始的 pending 证明在日历服务器上会保存一段时间，但不是永久的，所以最好在几天内完成升级。
