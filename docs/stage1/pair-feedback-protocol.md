# 两块一步前瞻：接口、成本和验收口径

最新架构及共享随机数配对约定见 [ARCHITECTURE.md](ARCHITECTURE.md)。本文的P(h)是已测greedy路径的简写；随机方案为P(h,u)，其中u与当前块GRU实际选词使用同一份。

本协议的B为跨块主干，D为整个16词解码链（GRU、VAE均值编解码和词表选择），E为历史编码器，P为反馈预测学生。D不是仅指VAE的并行还原头。

## 调度

组开始前保存干净cache与h。P(h)猜当前块A的反馈，B用这个猜测算出第二块的条件状态。D分别生成A和B。实际文字经过E得到真实反馈后，从组前cache重放这两个反馈，得到下一组状态。

重放只能纠正后续状态，不能改变已经生成的B。本轮始终保留B，是有损实验；没有实现阈值拒绝、无损验证或分布保持保证。

串行模式先后计算两次D，用于语义对照。batch模式等待两个条件状态齐备后，把它们沿batch维拼接，一次执行D。因此batch模式不是两个CUDA stream异步调度，也不声称D(A)在P之前已开始。

## Claude草案需要修正的成本口径

令b1为单位置主干耗时，b2为从干净cache重放两位置的耗时；d1/d2、e1/e2分别为1/2块的解码与编码耗时，p为学生耗时，v为验收开销。

在组前h已经准备好、拒绝时只提交A、下一轮再生成B的约定下，每轮期望推进1+α个块，批量方案的粗略周期为：

`C = p + b1 + d2 + e2 + v + α*b2 + (1-α)*b1`

`S ≈ (1+α)*(b1+d1+e1)/C`

若拒绝后在本周期立即重算B，则推进量和重算成本都应重新推导；至少还涉及真实条件下的D与E，不能只加B与P。自然EOS、变长batch和不同分支成本也会改变这个简化式。

不能把d2=d1、e2=e1或b2=b1当成一般事实；它们随模型、batch、上下文、算子实现和硬件变化。本轮组件计时与端到端计时分开报告，组件测试有时钟/宿主波动，不能用不同时间段的中位数拼出实测加速。

## 验收与监督

- 相对距离阈值只是有损启发式，不等于原教师分布保持。
- 固定历史的一步诊断应比较 `D(B(cache,f))` 与 `D(B(cache,P(h)))`，f不能直接跳过B送给D。
- teacher-forcing下平均CE低，不足以证明自由生成通过：第一词或前几词改变后，块内自回归会走向不同内容。
- 阈值在dev校准，test只报告预设曲线。离线候选覆盖率不是已实现拒绝调度器的端到端接受率。
- 错误注入需要检查方向及上下文相关性，不能默认各向同性高斯噪声等价于P的实际误差。
- 鲁棒训练是另一个实验：需要教师/基线副本、匹配的额外训练预算，以及更新B后P输入分布变化的控制。本轮没有开始修改B、D或E。
