# GRU 教师的反馈蒸馏：实验问题与负结果边界

采用已经实测可训练的16-token局部GRU教师。当前教师仅完成新增2000步，已经改善但仍有语法/连贯性错误，不能预先称为高质量教师。先固定一个可用教师及其采样策略，再蒸馏；不要同时改变教师与反馈学生而使目标漂移。

## 真正需要蒸馏的位置

把当前局部生成链统称为 T：h→GRU采词→VAE均值编码→D还原→实际文字y。历史压缩器记为G，下一块实际回灌r=G(y)。

若学生接收已经由GRU完成选词后才得到的z，C(z)只能替代后面的D/G，不能消除等待16次GRU选词的依赖。

若研究目标是让主干提前推进，学生应为 C(h,u)≈G(T(h,u))，其中u是教师这16次词表采样的同一组uniform随机数。两个分支同时获得h和u：教师继续产生实际文字，学生给出预测反馈让主干继续。

第一版用greedy教师，目标简化为C(h)≈G(T_greedy(h))。这更容易解释标签，但不保证容易拟合或保持教师质量。随机教师必须共用采样噪声；忽略噪声会把多种未来混进同一个回归标签。即使共用噪声，离散抽样产生的跳变也可能使映射难以近似。

## 单GPU收益不能预先保证

GRU增加了可以从主干关键依赖链中绕开的工作，但其实际输出仍必须完成。预测反馈不会自动减少总计算量。需实际测量单请求全部输出完成的耗时、首段文字延迟及稳定输出速度；分别计入学生、GRU、VAE和主干。仅将模型调用次数减少或两段理论耗时相加，均不能证明加速。

EOS属于真实文字路径的决定。若学生已提前生成后续latent，教师迟到的EOS可能使这些工作被丢弃，计时必须包含这种浪费；不能把错误反馈回写进已被使用的缓存却忽略重算成本。

## 最小可解释实验

1. 精确反馈教师作为质量与耗时基线。
2. teacher自由轨迹采集(h,u,r)，按故事/prompt划分训练与验证，冻结教师。拟合小MLP并测独立轨迹单步误差。
3. 用学生反馈连续推进32/64/128token，教师分支产生实际文字。评估上下文错配、反馈误差累积、实际文字质量与端到端耗时。
4. 若teacher轨迹训练单步误差很小但闭环差，用学生访问状态上的teacher反馈重新采样/训练作控制，区分近似容量与状态分布偏移。
5. 在较小矩阵上比较块长4/8/16、学生容量、greedy与共享噪声教师，至少重复关键配置的随机种子。

改变块长需匹配VAE与教师，不可直接把16词检查点当作4词模型，也不能用未收敛教师与已收敛教师比较后归因于蒸馏。

## 失败时可研究什么

可报告有范围的负结果，例如：在给定小模型、数据和预算下，低单步回灌误差不足以保持闭环文本质量；共享采样噪声使目标可定义，但不能保证可高效拟合；或单GPU上依赖缩短被学生与输出分支开销抵消。

需要有效教师、合理学生/训练控制、相同预算及完整计时，才能支持这些结论。一次训练失败不能证明反馈蒸馏普遍不可行，也不能把TinyStories实验推广到大规模多模态模型。

负结果可以构成研究内容，但论文价值和接受与否仍需看证据、新意与表达。arXiv同样有实质研究与学术价值审核，并非自动收录。参考：[一篇负结果预印本](https://arxiv.org/abs/2604.11867)、[arXiv审核政策](https://info.arxiv.org/help/moderation/index.html)。
