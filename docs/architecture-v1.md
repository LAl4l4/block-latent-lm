# Latent AR + Async Decoder：文本原型与多模态路线

记录日期：2026-10-22  
更新日期：2026-10-28  
状态：第一阶段同步训练与同步参考解码已实现并通过小规模运行检查；尚未完成正式质量实验或异步推理。后续多模态部分为研究路线，具体配置与训练方案待定。

## 1. 研究目标

长期目标是构建统一 latent 主干：由主干决定输出的内容及细节，轻量 decoder 将其还原为文本、图像、音频等形式。希望在压缩表示中完成主要生成计算，以减少重型主干的执行次数，并探索视觉等模态的生成训练是否能改善主干的世界理解和推理。

采用分阶段路线：**先完成当前文本异步原型，再扩展 decoder 和对应的主干训练。** 多模态能力与知识迁移不是第一阶段的交付要求。第 2–10 节描述第一阶段，第 12 节列出近期实现顺序，第 13 节记录后续路线。

第一阶段构建一个三模块的文本生成模型：prompt encoder 将输入文本压缩为 latent 序列，latent Transformer 在该序列上 prefill，然后自回归生成新的连续 latent；小型文本 decoder 将这些 latent 转化为文本 token。

核心问题是：**latent 主干能否不等待文本解码和 token 回灌，独立向前推进，并在保持生成质量的前提下获得实际效率收益？**

本课题同时涉及输入压缩、latent 自回归和异步执行。实验需要分别测量各部分贡献，不能仅凭 KV 更小或主干步数更少推断端到端更快。

## 2. 已确定的总体结构

```text
prompt tokens
    │
    ▼
Chunk Encoder：每 4 个 token → 一个 512 维 latent
    │
    ▼
Latent Transformer：对 prompt latents 做 prefill，建立自身 KV cache
    │
    ▼
自回归生成：z₁ ──→ z₂ ──→ z₃ ──→ …
             │       │       │
             ▼       ▼       ▼
          有界 latent 队列（推理时）
                     │
                     ▼
              小型 AR Text Decoder
                     │
                     ▼
                  文本 tokens
```

主干从 prefill 到后续生成始终接收 latent，不混入原始 token embedding。文本历史只在小型 decoder 内部反馈，已解码文本不回灌 latent 主干。

Encoder 负责产出 prompt latents；prefill 和 KV cache 的建立由 latent Transformer 完成。

## 3. 第一版架构配置

以下是起步配置，不代表已经验证有效的最优设置。

| 模块 | 配置 | 职责 |
|---|---|---|
| Prompt encoder | token embedding 256 维；每 4 个按顺序拼接；MLP 映射到 512 维；末尾归一化 | 压缩输入文本 |
| Latent Transformer | 8 层，宽度 512，8 个 attention heads，SwiGLU 中间维度 1536，RoPE，causal attention | 处理 prompt latents，自回归生成后续状态 |
| Latent 输出接口 | 小型 512→512 投影及归一化 | 将主干输出变为下一步可回灌的 latent |
| Text decoder | 2 层，宽度 256；causal self-attention + latent cross-attention | 维护文本历史，并读取已可用的 latent |
| 输出节奏 | 每个新生成 latent 对应最多 4 个输出 token 的预算 | 固定首版流式对齐规则 |

第一版采用确定性的 latent 状态，随机性放在文本 decoder 的 token 采样中。暂不加入随机 latent head、VAE、latent MSE 目标或单独的 autoencoder 预训练。

这是第一阶段的原型选择：当前 decoder 仍参与具体措辞的生成，尚未实现长期目标中的“内容和细节全部由主干确定”。后续若采用严格的还原式 decoder，需要重新设计 latent 输出与训练目标，把生成决策和必要的随机性移到主干端；本阶段不提前引入这些改动。

Tokenizer 的具体实现和词表大小尚未最终确定；所有对照实验必须使用同一个 tokenizer。约 8k 词表可作为小规模实验候选。

注意：“每个 latent 对应 4 个输出 token”首先是一条解码调度规则，不代表生成 latent 已被证明是这 4 个具体 token 的可逆编码。

该规则仅用于文本原型，不是跨模态接口的永久约束。后续输出单位可以是图像块、音频片段或其他有明确边界的表示。

## 4. Prompt 压缩与边界对齐

Prompt 按输入顺序每 4 个 token 分块。最后不足 4 个 token 的块仍产生一个 latent。

例如 prompt 有 10 个 token：

```text
[x₁ x₂ x₃ x₄] → u₁
[x₅ x₆ x₇ x₈] → u₂
[x₉ x₁₀     ] → u₃，有效长度为 2
```

固定尺寸 MLP 的缺失槽位可以置零，同时显式提供有效位置 mask 或有效长度信息。补齐只发生在计算张量中，不向真实文本添加空格或其他字符。

输出从 prompt 边界重新分块：

```text
z₁ → y₁ … y₄
z₂ → y₅ … y₈
```

不要求首批输出先补满 prompt 的最后一个块。训练和推理必须采用相同的边界规则；不得用真实续写补满 prompt 尾块。

## 5. 模型依赖与条件分布

记输入 prompt 为 p，续写为 y，prompt encoder 为 E，latent 主干为 F，回灌接口为 A，文本 decoder 为 D。

```text
U = E(p)
zₜ = A(F(U, z₁, …, zₜ₋₁) 的最后一个 hidden state)
```

实际实现使用 KV cache，避免每一步重新计算完整前缀。第一步的 z₁ 由 prompt prefill 的最后一个有效 hidden state 产生。

输出第 j 个 token 时，允许读取的生成 latent 数量为：

```text
t(j) = ceil(j / 4)
p(yⱼ | p, y<ⱼ) = D(y<ⱼ, U, z₁ … zₜ₍ⱼ₎)
```

Decoder 的 cross-attention 必须严格限制到当前已允许读取的 latent；即使异步主干已经提前生成更多 latent，也不能提前暴露给当前文本位置。

默认让 decoder 通过 prompt latents 读取输入信息；续写 token 历史通过其自身的 causal self-attention 维护。Latent 主干不接收续写 token。

## 6. 训练方案：直接使用文本 CE

三个模块联合训练，梯度路径为：

```text
文本 token CE → Text Decoder → Latent Transformer → Prompt Encoder
```

损失是所有有效续写位置上的负对数概率之和或均值：

```text
L = -Σⱼ log D(yⱼ | y<ⱼ, U, z≤ceil(j/4))
```

训练流程：

1. 将故事切分为 prompt 和续写；encoder 只能看到 prompt。
2. 编码 prompt，并在 latent Transformer 中完成 prefill。
3. 展开 latent 链，每一步使用主干自己产生的 latent。
4. 文本 decoder 使用真实的历史续写 token 做 teacher forcing，并按严格的 latent 可见性 mask 计算 CE。
5. 保留 latent 链及相关缓存的计算图，反向传播更新全部模块。

训练时不要把真实后续文本编码成 latent 后喂给主干，却在推理时改成纯 latent 回灌；这会引入额外的训练与推理差异。

文本 decoder 的 teacher forcing 计算可以并行化，但 latent 链仍需要逐步展开。KV cache 可减少重复计算，不能消除这一串行依赖。随意 detach latent 或缓存会改变梯度传播范围，不能作为默认的无影响优化。

训练代码先同步执行并保持可微；异步执行作为后续推理优化单独实现。

## 7. 异步推理与停止规则

Latent Transformer 作为 producer，文本 decoder 作为 consumer，中间使用有界队列。Producer 可以超前生成少量 latent，consumer 按编号消费。队列容量和最大超前步数通过后续测量确定。

Decoder 消费 zₜ 后，获得第 t 个输出块的生成预算，并继续维护自己的文本 KV cache。不同块之间的文本依赖由 decoder 保持。

文本遇到 EOS 时结束输出，并通知 producer 停止；允许丢弃少量已经提前计算但尚未消费的 latent。停止通知和队列背压属于执行控制，不包含文本语义回灌。

设置最大生成 token 数和最大 latent 步数，避免无限运行。Batch padding 的标签不计算 CE；自然文档结束可以监督 EOS，因窗口长度而截断的样本不要伪造文档结束标签。

单卡上的两个执行流不保证产生实际重叠或加速，需要计入调度、缓存和 decoder 成本后测量。

## 8. 数据集与最小实验

第一阶段使用 [TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories)。它适合低成本训练小型文本生成模型；本轮主要验证架构和自由生成稳定性，不据此声称推理能力提升。

起步安排：

- 先取约 1,000 篇做过拟合与流程检查。
- 第一轮正式实验从官方 train 固定随机抽取约 10 万篇，记录 seed 和样本清单。
- 官方 validation 划分为调参集和最终测试集，按故事隔离。
- Encoder、tokenizer（若自行训练）及其余模块只使用训练数据训练。
- 最初只展开 16 个 latent，最多生成 64 个输出 token；通过后再扩展到 32、64 个 latent。
- 当前实现的起步配置为 prompt 最长 128 token、AdamW、学习率 3e-4、batch size 64、梯度累计 2 次（有效批量 128），每 100 步自动保存。2026-10-29 的本机实际训练日志支持该批量；这些数值不是调参结论，配置以 `configs/overfit.json` 和 `configs/train.json` 为准。

## 9. 必须保留的对照与评价

| 对照 | 目的 |
|---|---|
| 普通 token AR 模型 | 判断完整方案相对常规生成是否值得 |
| Prompt encoder + 同尺寸文本 decoder，移除生成 latent 分支 | 判断自由推进的 latent 主干是否提供收益 |
| 完整模型的同步与异步推理 | 隔离异步执行本身的贡献 |
| 生成 latents 置零或打乱的诊断 | 检查 decoder 是否实际利用生成 latent |

比较时记录参数量、实际训练 token 数、训练计算预算与推理条件。消融引起的分布变化需要谨慎解释，不能仅凭一次打乱实验证明模型的内部机制。

主要评价：

- 有效续写位置上的验证 CE，以及自由生成的连贯性、重复和上下文一致性。
- 随生成长度增加，质量是否持续退化。
- Latent 分支是否带来超过同尺寸 decoder 对照的收益。
- 在相近质量下的端到端耗时、首 token 延迟、输出吞吐和峰值显存。
- 同步与异步推理在相同随机数、采样设置和可见性规则下的输出一致性。

开放故事续写有多种合理答案，不能使用与原文完全一致的比例作为主要生成质量指标。

## 10. 待验证的研究假设

1. **统一 latent 输入有利于优化。** 主干只接收 latent 可统一输入粒度，但“混合 token/latent 一定导致严重 attention 优化问题”尚未被本项目证明。
2. **两类 latent 可以学会兼容。** E(prompt chunk) 与主干生成的 z 即使维度相同，也不保证具有同样的分布或语义。第一版让联合 CE 学习兼容关系，不强制逐块表示相等。
3. **主干可以在没有文本反馈时保持长期有效。** 主干不知道 decoder 实际采样出了哪条文本路径，这可能限制长期计划与文本的一致性。
4. **小 decoder 会使用生成 latent。** 它可能主要依靠自身的文本历史和 prompt latents 完成任务，需要对照验证。
5. **计算节省能转化为实际加速。** Latent 训练的串行展开、decoder 开销和异步执行竞争都可能抵消收益。
6. **输入压缩保留足够细节。** 名字、数字和精确复制能力需要特别观察。

这些假设是实验对象，不是当前方案已经达到的性质。

## 11. 与已查阅工作的关系

### CALM

[Continuous Autoregressive Language Models](https://arxiv.org/html/2510.27688v1) 使用 chunk autoencoder 和连续向量生成。其最终实现采用解码后的文本 token 反馈，并报告直接 latent 输入导致性能下降。本项目要测试的是移除逐步文本反馈后的独立 latent 推进，因此不能直接继承其性能结论。

### Coconut

[Training Large Language Models to Reason in a Continuous Latent Space](https://arxiv.org/html/2412.06769v4#S3) 展示了 hidden state 回灌、由后续文本 CE 训练的可微路径，也指出 latent 展开带来的串行训练成本。其任务设置和生成架构与本项目不同。

### DeepSeek-V4.1-Flash

[官方技术报告](https://arxiv.org/html/2609.19969v1) 的 CED 使用 encoder 最终 hidden states 构建 decoder 的全局 KV。其 encoder 部分 CSA2 层使用 2:1 全局 KV 压缩，decoder CSA2 压缩率为 1，并保留局部滑窗 attention。这里压缩的是 attention 记忆条目，不能等同于自主 latent AR 或异步文本生成。

### 视觉生成与知识迁移：后续研究动机

[Video models are zero-shot learners and reasoners](https://arxiv.org/html/2509.20328v1) 展示了视频生成系统在感知、物体操作、直觉物理以及部分视觉推理任务上的零样本能力。其评估系统包含语言模型提示词改写，不能将全部能力直接归因于纯视觉生成网络，也不能据此推断视觉模型在世界理解上全面超过文本 frontier 模型。

[Can Visual Generation Expand What Unified Multimodal Models Know?](https://arxiv.org/html/2610.21459v1) 通过只在图像生成训练的目标图像中提供新事实，再测试纯文本问答，观察到直接但不完整的知识迁移；跨模态对齐监督可改善知识的可访问性。这支持后续研究视觉生成训练对共享主干的作用，但不证明本项目的 latent 架构已经具备该能力。

本项目第一阶段的重点是 **prompt 压缩后，主干在不等待文本回灌的条件下持续生成 latent，再由独立的小型 AR decoder 输出文本**。目前尚未完成全面的新颖性检索或正式质量与效率实验；已有检查仅验证实现流程。

## 12. 第一阶段实现顺序与阶段判断

当前代码入口与用法见 [README.md](../README.md)，运行检查记录见 [VALIDATION.md](../VALIDATION.md)。已提供分块 encoder、可微 latent rollout、同步 CE 训练、同步生成和无 latent 分支对照开关；有界队列、异步推理、普通 token AR 基线与正式对照实验仍待完成。

1. 完成分块 encoder、边界 mask 和小型文本 decoder。
2. 实现 latent prefill、自由回灌和 16 步可微展开。
3. 跑通直接 CE 训练及短文本自由生成。
4. 完成无生成 latent 分支等基本对照。
5. 实现有界队列和异步推理，验证输出一致性并测量真实速度。
6. 根据结果再考虑更长 rollout、额外表示约束或其他架构调整。

进入后续扩展前，先形成可复现的第一阶段结论：

- 短文本自由生成与 latent 回灌可稳定运行，并完成随 rollout 长度变化的评价。
- 完成无生成 latent 分支等对照，判断主干分支是否提供实际收益。
- 同步与异步执行满足相同的可见性、停止和采样规则，记录输出一致性及差异原因。
- 在相近质量下报告端到端耗时、首 token 延迟、吞吐与显存，而不是仅报告主干步数。

通过流程检查不等于获得效率收益。若没有收益，应定位问题并决定是否调整第一阶段方案；不能用后续多模态愿景替代当前实验结论。暂不预设未经测量的质量或加速阈值。

## 13. 后续路线：扩展轻量 decoder 与统一主干能力

### 13.1 目标职责

文本阶段完成后，逐步加入图像和音频输出。最终希望主干生成的 latent 足以确定目标输出的内容与细节，decoder 只执行低成本还原。图像或语音的生成能力属于统一主干，不依赖推理时调用另一个负责创作的图像模型或 TTS 模型。

```text
输入 → Encoder → 统一 Latent Transformer → 继续 latent 回灌
                              │
                   带模态、位置和边界信息的输出 latent
                              │
                 ┌────────────┼────────────┐
                 ▼            ▼            ▼
             文本还原器    图像还原器    音频还原器
                 │            │            │
              文本块        图像块       音频片段
```

图示表示可选择的输出路径，不要求每次都输出全部模态，也不要求同一个 latent 向量同时充当文字、像素和波形的编码。可以共享主干参数与内部计算宽度，同时保留各模态必要的位置结构和输出接口。输出侧扩展可先保留文本输入，多模态输入 encoder 的加入另行设计。

长期目标下，必要的随机性在主干的 latent 生成过程中完成；给定相同 latent 和解码状态，decoder 应产生确定的输出。仅有确定性不足以证明 decoder 只负责还原，还需要限制其计算和容量，并检验 latent 对具体内容的控制。

“细节由主干定义”是职责要求，不代表有限 latent 可以无损压缩任意高清图像或波形。需要明确保真要求、latent 数量与数值精度，并测量重建误差。压缩过强时，不能依赖下游复杂生成器补全细节来替代这一目标。

### 13.2 扩展入口与训练调整

扩展 decoder 是架构入口；获得新模态能力仍需训练主干。只增加或训练 decoder、保持未经相应训练的文本主干不变，不能预期获得完整的图像或音频生成能力。

后续需要逐项确定：

| 项目 | 待研究内容 |
|---|---|
| 表示与还原 | 文本块、图像空间块、音频时间片段的编码方式、容量与轻量 decoder |
| 主干输出 | 如何生成有效且细节充分的 latent；随机性、模态选择与结束边界如何由主干表达 |
| 训练目标 | 各模态重建与生成目标，以及主干自由回灌后的稳定性 |
| 调度 | 各模态可见性、消费粒度、缓冲、停止与延迟；多输出时使用独立读取位置或队列 |

可考虑先训练 encoder–decoder codec，再训练主干生成编码，或探索联合训练；目前不固定方案。如果后续改用真实历史编码做 teacher forcing，必须明确它与第一阶段自由 latent 展开的差别，并测试推理时生成编码回灌的暴露偏差。

文本准确还原、图像细节保持和音频波形保真需要分别评价。若同时输出语音与字幕，需单独训练并检验对应关系；共享主干不会自动保证逐字一致。

### 13.3 世界理解与推理迁移

后续研究假设是：当 decoder 只负责还原时，主干为了生成正确的图像、声音或状态变化，需要学习相应结构和规律；这些能力有可能被同一主干用于语言回答与推理。

共享参数、共享维度或生成损失回传都不能自动保证知识可被其他任务调用。应围绕相同场景组织生成、理解和预测任务，例如视角变换、遮挡关系、动作后的状态预测，以及对应的空间问题回答。涉及动态或因果规律时，需要视频、动作条件或可核对的状态变化监督，不能仅凭静态画面逼真宣称理解物理。

如利用已有视觉模型，教师可在训练时提供经核验的样本或表示，最终推理仍由本项目主干完成。单纯复用图像 codec 或末端 decoder，不等于继承原生成主干的世界知识；是否使用教师及具体迁移方式仍待实验设计。

### 13.4 分开验证生成能力、知识迁移与效率

后续评价需要区分三个问题：

1. **生成能力：**主干能否生成可被轻量 decoder 准确还原的多模态 latent，且细节和跨模态关系正确？
2. **知识迁移：**增加视觉生成或状态预测训练后，主干在未见过的场景组合、语言回答或推理任务上是否改善？
3. **效率：**达到相近质量时，减少的主干计算是否超过新增的表示生成、解码和调度成本？

迁移实验可比较仅训练问答、加入视觉理解、进一步加入视觉生成或状态预测的模型。控制或分别报告模型规模、数据来源与计算预算，隔离测试场景，避免把额外数据或更长训练的收益直接归因于架构。可另设知识仅出现在视觉监督中的样本，用纯文本问答检验可访问性。

主干读取自己生成的视觉 latent 并继续推理，是后续可探索的路径；中间表示不一定需要还原成像素。但其可读取性、预测正确性与误差积累需要训练和测试，不属于第一阶段实现承诺。

当前优先级始终是完成第 12 节的文本实验。后续扩展沿用经过验证的接口与执行机制，具体模态顺序、模型规模、数据和训练目标依据第一阶段结果决定。
